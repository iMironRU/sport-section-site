# Стек и архитектура

Версия 0.1, 7 октября 2026. Основано на наших проектах: `labpechatey.ru`,
`orgmu-site`, `goldmean.ru` (статические сайты), `http-server-1c`
(JSON-RPC для 1С), `kabitoriy` (личный кабинет на 1С/БСП с тонким React),
`chronicon` (порт публикации из 1С на сайт).

## 1. Принцип

Три контура, каждый на том, что у нас уже отработано:

| Контур | Что | Стек | Кто работает |
|---|---|---|---|
| **Сайт** | Публичная часть, ~60 страниц, SEO, сведения | Next.js 16 App Router, `output: "export"`, React 19, TypeScript, Tailwind 4; контент YAML/JSON в репо | Родители, проверяющие, поисковики |
| **Ядро** | Данные и процессы: группы, зачисления, абонементы, платежи, документы, посещаемость, отчёты | 1С:Предприятие 8.3 на БСП, самостоятельная конфигурация; `http_HTTPСервер` даёт JSON-RPC 2.0 + JWT; OIDC-провайдер для входа | Администратор, руководство, бухгалтер, медработник в 1С |
| **Кабинет** | Родитель, тренер, спортсмен, руководитель отделения | Тонкий React-клиент (Vite, PWA) поверх JSON-RPC ядра; паттерн Кабитория: схема с сервера, агрегированный профиль одним вызовом, заявка как центральный объект | Родители и тренеры с телефона |

Сайт не знает ядра напрямую: он собирается из файлов, а живые данные
(группы, места, отмены) получает снимками, которые публикует ядро. Кабинет
говорит только с ядром. Ядро не рендерит HTML.

## 2. Публичный сайт

- Копия подхода `orgmu-site`: `src/app` маршруты, `content/` данные, `scripts/` парсеры и сборка, `design-ref/` макеты дизайнера, `AGENTS.md` правила. Сборка на webpack для детерминизма (`next build --webpack`), `generateBuildId` от коммита кода.
- Контент двух сортов:
  - **редакционный** в репо: направления, программы, тренеры, объекты, тарифы, документы, страницы, новости, FAQ. Правит администратор через коммит или через 1С, откуда выгружается в `content/` (см. порт публикации).
  - **оперативный** из ядра: группы с местами и статусом, расписание, отмены и замены, события, достижения, счётчики. Ядро публикует `public/data/*.json` снимками.
- Два способа доставки оперативных данных, выбираются конфигом:
  - **пересборка**: ядро коммитит снимок в репо (GitHub App или FTP на сервер сборки), CI пересобирает. Задержка минуты. Подходит школе с редкими изменениями.
  - **рантайм**: страница рендерится со снимком из сборки, а в браузере дотягивает свежий `data/groups.json` с хоста ядра по CORS, как рейтинговые списки у ОрГМУ. Для мест и отмен обязателен этот путь: NFR-06 требует минуту.
- Формы заявок: движок форм из `orgmu-site` (`src/lib/forms`, yml-конфиг, honeypot, тайм-трап) шлёт JSON-RPC в ядро. Пока `NEXT_PUBLIC_API_BASE` пуст, работают моки, как в `labpechatey.ru`, сайт показывается целиком без бэкенда.
- Режимы и опции: `content/site.yml` с флагами из PLAN.md 4; шаблоны читают словарь терминов оттуда.
- Два режима деплоя одновременно, как у ОрГМУ: GitHub Pages для демо и FTP-синхронизация по md5 на хостинг школы. Поддомены филиалов: один репо, `NEXT_PUBLIC_BRANCH`, отдельные сборки.
- Версия для слабовидящих, микроразметка, Метрика: переносятся из `orgmu-site`.

## 3. Ядро на 1С

- **Форма поставки**: самостоятельная конфигурация на БСП 3.1 (как `kabitoriy/1c/standalone`), не расширение к типовой: у спортшколы нет «хост-конфигурации», а бухгалтерия подключается обменом БСП с 1С:Бухгалтерией или выгрузкой (REP-09).
- **Подсистемы** один в один с разделами REQUIREMENTS.md: Набор (LEAD), Группы и сезоны (GRP), Семьи и аккаунты (ACC), Тарифы и абонементы (PAY), Договоры (CTR), Посещаемость (ATT), Документы (DOC), События (EVT), Прогресс (PRG), Безопасность (SAFE), Уведомления (NTF), Отчёты (REP), Настройки и филиалы (CFG), Сведения (SVD). Справочники по PLAN.md 4 и связи по 4a.
- **Что берём из БСП**: Управление доступом (роли и профили), Присоединённые файлы (сканы документов), Версионирование и Журнал регистрации (аудит ACC-12), Обмен данными (бухгалтерия), Регламентные задания (напоминания, сгорание кредитов), Бизнес-процессы и задачи (воронка заявок, задачи администратору), Печать (договоры, заявки федераций из макетов), Электронная подпись где применимо, Варианты отчётов и СКД (REP).
- **HTTP-слой**: `http_HTTPСервер` как есть: конвейер, JSON-RPC, Bearer JWT, API-ключи для интеграций, идемпотентность по `Idempotency-Key` (платежи, вебхуки), журнал запросов, Swagger. Каждая подсистема регистрирует методы через модуль `*HTTPПодсистема`.
- **Авторизация**: `OpenIDConnectProvider` из `http-server-1c` как сервер входа. Вход по телефону с кодом (SMS или Telegram), VK ID, Яндекс ID, Telegram Login подключаются как внешние провайдеры к нему, он выдаёт JWT. Госуслуги для лицензированного режима через ЕСИА, требует аккредитации организации; закладываем как провайдер, включаем позже. Один аккаунт = один пользователь ИБ с ролями из ACC-02; привязка способов входа в справочнике.
- **Деньги**: как в Кабитории, ядро не биллинг-движок, а учёт обязательств и платежей. Платёжный шлюз через адаптеры: СБП (банк или агрегатор), эквайринг, онлайн-касса. Инициация через Outbox, подтверждение вебхуком с дедупом. Кассовая ссылка PAY-09 это документ «Счёт на оплату» с внешней ссылкой шлюза.
- **Уведомления**: Outbox в регистре сведений, `DeliveryProvider` по каналам. Почта и SMS прямо из 1С, Telegram и web-push через коннектор (п. 5). Матрица тип × канал NTF-03 как регистр настроек пользователя.
- **Порт публикации**: по образцу Хроникона. Регламентное задание собирает снимки `groups.json`, `schedule.json`, `events.json`, `achievements.json`, `counters.json`, редакционный контент в YAML и отправляет на хост сайта (FTP или HTTP PUT) и, при режиме пересборки, в репо. Согласия на публикацию имён проверяются здесь, на сайт имена без согласия не попадают.
- **Хостинг ядра**: VPS школы или наш, Linux, сервер 1С или файловая база для маленькой секции, публикация через Apache (есть навыки web-publish). 1С:Фреш не подходит: нужна своя конфигурация и расширения HTTP.
- **Мультиарендность**: один инстанс на школу или сеть, как у Кабитория. Филиалы внутри одной базы (CFG-06). NFR-08 трактуем как «один шаблон, много независимых установок», не как SaaS с общей базой. Если позже нужен SaaS, это отдельное решение.

## 4. Кабинет

- Отдельное приложение, не часть статического сайта: React 19, TypeScript, Vite, Tailwind 4, те же токены и компоненты, что у сайта (общий пакет `ui/`). Собирается в статику и живёт на том же хостинге по адресу `/lk/`, ходит в ядро по JSON-RPC с JWT.
- **PWA**: установка на телефон, push-уведомления, офлайн-журнал тренера (NFR-09): отметки складываются локально и синхронизируются с `Idempotency-Key`.
- Паттерн Кабитория для всего, что похоже на заявку: запись, лист ожидания, заявление на перевод и отчисление, регистрация на событие, подписание документов. Схема формы и статусы приходят с сервера, фронт рендерит и валидирует как зеркало.
- Разделы по ролям из PLAN.md 7: меню собирается из ролей в JWT, контекст «как тренер / как родитель» хранится на клиенте.
- Чаты COM-01..02: сообщения в ядре, доставка в реальном времени через коннектор (SSE или WebSocket), в 1С только хранение и правила доступа.
- Демо-режим с моками, как у сайта: кабинет показывается без ядра.

## 5. Коннектор

Маленький Node-сервис (Hono, как в `imiron-case-app`, на Cloudflare Worker или на том же VPS) для того, что 1С делает плохо или не делает:

- Telegram-бот: вход по телефону через Telegram, уведомления, приём заявок в чат школы.
- Web-push для PWA.
- Вебхуки платёжных шлюзов и СМС-провайдеров → JSON-RPC в ядро с идемпотентностью.
- SSE для чатов и живых обновлений кабинета.
- Загрузка файлов с телефона с предобработкой изображений перед передачей в 1С.

Коннектор без состояния, вся истина в ядре.

## 6. Интеграции

| Что | Как |
|---|---|
| СБП, эквайринг, касса | Адаптеры в ядре, вебхуки через коннектор |
| SMS | Провайдер по HTTP из 1С |
| Telegram | Коннектор |
| VK ID, Яндекс ID | OIDC-провайдер ядра |
| Госуслуги | ЕСИА через OIDC, после аккредитации |
| 1С:Бухгалтерия | Обмен БСП или выгрузка |
| ФГИС «Спорт», Навигатор ДО | Выгрузки CSV/XML по их форматам, CFG-11 |
| Федерации | Печатные формы заявок из макетов, EVT-11 |
| Страховщик | Партнёрская ссылка с возвратом полиса вебхуком, DOC-12 |
| Карты, Метрика, DaData | Как в `orgmu-site`, фасады без трекеров до согласия |

## 8. Среды и деплой

- **Демо**: GitHub Pages для сайта и кабинета с моками, без ядра. Показ заказчику и дизайнеру.
- **Пилот**: VPS с 1С и коннектором, сайт и кабинет по FTP на тот же VPS или хостинг школы.
- CI: как у ОрГМУ, `deploy.yml` сборка и Pages плюс FTP, `concurrency` без отмены. Для 1С: сборка .cf и тесты в CI на Windows-раннере или вручную по навыкам `cf-build`, `test-yaxunit`.

## 9. Что не решено

1. Платёжный агрегатор для СБП и кассы: выбирается по комиссии и наличию тестовой среды.
2. Хостинг ядра у школы или у нас: влияет на SLA NFR-05 и резервные копии NFR-07.
3. Web-push в России: Safari на iOS поддерживает PWA-push с 16.4, но Telegram-канал надёжнее; делаем Telegram основным каналом push.
4. Госуслуги: аккредитация ЕСИА занимает месяцы, в первой версии вход по телефону и VK.
5. Нужен ли обмен с 1С:Бухгалтерией или достаточно выгрузки: решит бухгалтер пилотной школы.
